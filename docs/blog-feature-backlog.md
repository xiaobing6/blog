# 个人介绍与技术博客功能候选清单

> 更新日期：2026-07-26  
> 状态：候选功能基线  
> 适用目标：用于个人介绍、技术能力展示、项目沉淀和技术文章总结，让首次访问者更快了解作者并找到可信的能力证据。

## Phase 1 状态（2026-07-26）

以下原候选能力已经落地，不再属于“未实现”：个人首页与关于页、真实项目列表、统一资料数据、草稿/未来日期过滤、精选与分类字段、最新/精选文章、上下篇与相关文章、阅读时长、二三级目录、代码复制、文章 SEO 与 JSON-LD、亮暗主题、跳过链接与减少动画、标签总览、分类、归档、Pagefind 文章全文搜索、RSS 完善、格式/类型/构建检查和发布清单。

仍未完成的第一批内容主要是：

- 需要真实资料：更多代表项目、代表文章、经历时间线、头像、所在地、邮箱或其他确认公开的联系方式。
- 需要 Cloudflare 配置：为 `PUBLIC_CF_WEB_ANALYTICS_TOKEN` 提供真实令牌并验证线上数据。
- 需要部署后验证：本次代码上线后的公网路由、搜索索引、RSS、Sitemap 与社交分享卡片。

下方表格保留最初评估基线；判断“尚未实现”时，应排除本节已完成项。

## 1. 文档用途

本文档记录当前项目尚未实现或只实现了一部分、且对个人介绍与技术分享站点可能有价值的功能。它是长期 Backlog，不表示所有功能都应该立即实现。

优先级定义：

- `P0`：第一批，直接影响“别人能否快速了解我”或内容发布安全。
- `P1`：内容开始增长后价值明显，适合第二批。
- `P2`：有明确需求时再做。
- `P3`：平台化能力，当前个人站通常不值得承担复杂度。

工作量定义：

- `S`：局部数据、组件或配置改动。
- `M`：涉及多个页面、组件或构建流程。
- `L`：涉及信息架构、外部服务或较多交互。
- `XL`：接近平台或 CMS 建设。

## 2. 当前已有的基础能力

以下功能已经存在，不进入缺失功能清单：

- Astro 静态站点和 Cloudflare Pages 部署。
- Markdown、MDX、Content Collections 和 Frontmatter 校验。
- 首页、博客列表、文章详情、关于页、标签详情页和 404 页面。
- 发布时间、更新时间、摘要、封面图和标签。
- 响应式页面、Astro 图片处理、基础代码高亮。
- Canonical、基础 Open Graph、Twitter Card。
- RSS、Sitemap 和 robots.txt。

当前仍有两个“部分实现”问题：

- 文章页没有把 `heroImage` 传给 Head，因此文章分享图仍会回退到统一占位图。
- 所有页面的 `og:type` 都是 `website`，文章页还不是完整的文章 SEO 实现。

## 13. 决策原则

后续从 Backlog 选择功能时遵循以下原则：

1. 优先帮助访客回答四个问题：你是谁、你擅长什么、你做过什么、如何联系你。
2. 每个能力声明都尽量链接到项目、文章或可验证的外部记录。
3. 发布安全、内容可读性和可发现性优先于装饰性动画。
4. 维持静态站架构；搜索、评论和统计优先选择不需要自建服务器的方案。
5. 没有真实内容和数据时，不实现热门排行、虚假阅读量或空的社交入口。
6. 引入外部服务前先确认隐私、可用性、费用和长期迁移成本。
7. 每完成一批功能，更新本文档状态并从实施计划中回链对应 ID。
